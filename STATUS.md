# STATUS

**Where the programme stands, between sessions.** *A status reply reads this file rather than recomputing the position, so the judgement in it is one a later reader can argue with instead of one re-invented every time it is asked for.*

**EACH JUDGEMENT SECTION CARRIES ITS WORD BUDGET AND ITS LAST-UPDATED STAMP IN ITS OWN HEADING, AND [status_report.py](scripts/misc/status_report.py) CHECKS BOTH.** *The stamp is VERIFIED rather than trusted: the script diffs each section against the committed version and reports any whose text moved without the stamp moving with it, so a stale stamp is as visible as a stale count.* *A position file with no ceiling becomes a second copy of the record, and the copy drifts. The budget forces a rewrite rather than an append, which is the only thing that keeps this readable at a glance.*

**How the two judgement sections are written.** *The chain is one node per line and never run together, since a sentence saying which path an item is on lets a missing link pass unread.* **The share is one percentage, never a band.** *A judgement, not a count: weigh what is proved by how much of the REMAINING difficulty it removes. The open node is usually the hardest, so an honest figure sits below the fraction of nodes standing.* *Never report the goal as a single unproved statement and call that 0%: that number is the same on the first cycle and on the last one before the proof closes.* **The estimate names what it rests on in one clause**, so the reader argues with the weighting rather than with the number.

**Two halves, and they are maintained differently.** The block below the marker is GENERATED by [status_report.py](scripts/misc/status_report.py) and is never edited by hand. Everything above it is a JUDGEMENT, written by the cycle that changed it and carrying the reason, because nothing can count the share of a proof that is done.

**What this file does NOT hold**: anything owed to the user, which lives in [DECISIONS-TO-MAKE.md](DECISIONS-TO-MAKE.md); the task list, which is [plan.md](plan.md); and the mathematics, which is [findings/](findings/).
