# Index, traps and proven negatives

**What bites, and what has already been ruled out.** Read before proposing a route or believing a screen. Two kinds of entry:

- **The fence posts**, proven or machine-verified negatives. *A route one of them already kills is the most expensive kind of proposal, because it looks new.* Each row names the file where the post is stated in full; several live outside [fence-posts.md](fence-posts.md).

**In [fence-posts.md](fence-posts.md) every post is its own `## Post N,` heading**, so `grep -n "^## Post F34" findings/` goes straight to it. The 22 posts held in [second-order.md](second-order.md), [bounds.md](bounds.md), [target.md](target.md) and [bispectral.md](bispectral.md) do not yet carry that heading form and are found by number search instead.
- **The warnings**, `W1`…`W7`, each a screen or an object that behaves differently from how the record's vocabulary suggests. Cited by id.
- **The standing rules**, the methodological traps this programme has paid to learn, one line each, stated in full in [LEDGER.md](LEDGER.md).

Results by number: [INDEX-results.md](INDEX-results.md). Values: [INDEX-values.md](INDEX-values.md). Which file for which subject: [INDEX.md](INDEX.md).
