# Analysis only, unless a task is approved for computation

**The user has put this programme on an analysis-only footing. A LONG or OPEN-ENDED run requires explicit approval for the specific task, and the approval does not carry to the next one. A run of a few minutes does not.**

What remains permitted without asking: **screening a claim you are about to record**, seconds of compute on objects you construct for that purpose, reported as a screen and never as evidence for a positive claim. **AND ANY RUN THAT FINISHES IN A FEW MINUTES ON OBJECTS ALREADY IN HAND: SOLVE THE SYSTEM, EVALUATE THE CANDIDATE, CHECK THE CASE.** *Asking costs the user a decision worth less than the run, and a cycle that stops for permission on minutes of arithmetic has spent more of their attention than the arithmetic was worth.*

**What still waits is scale and open-endedness, not computation itself**: a sweep over a parameter range, a census of a family, an optimisation whose cost is unknown before it starts, a falsifier hunt with no bound on where it looks. *The test is whether you can say in advance what it will cost and what it will decide.* When you cannot, name it and stop.

**When a plan item needs a run that is long or open-ended, say so and stop.** Name what the run would decide and what each outcome would mean, then wait. An item blocked this way stays on the list with the block recorded against it; it is not quietly worked around, and it is not started on the assumption that the answer will be interesting enough to justify itself afterwards.

**The reason this is a standing rule rather than a preference.** The session that prompted it produced its strongest results by hand (a completeness theorem for the per-index relations, two lemmas, and the discovery that both of the programme's standing spectral bounds are one system read at two rows) while the numerical work of the same session mostly produced figures that later had to be withdrawn, and one that omitted a relation and was cited for hours as if it had not. Analysis also leaves an argument a reader can check, which is what this programme is for.

**Reviewers inherit the rule.** State it in every brief, with the screening allowance spelled out, so a subagent does not open a numerical line of work the parent would not have opened.
