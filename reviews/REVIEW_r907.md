## 2. The closing-line predicate

**The repair works, and it is the strongest thing in the fold.** I extracted both pattern strings from their files rather than retyping either.

- **They are identical character for character**, `[\s\[\]0-9:.\-TZ]*(DONE|FAILED)\b` in both [salvage_reviewer.py:42](../scripts/lib/salvage_reviewer.py#L42) and [loop_stop.py:491](../.claude/hooks/loop_stop.py#L491), and both are applied with `re.match`, so the anchoring is the same.
- **The split is closed on the real corpus.** Over all 1509 logs in [agent_logs/](../agent_logs/), replicating each reader's own windowing, the old predicate leaves 350 logs read closed by the hook and open by the tool, which reproduces r906's figure exactly on 7 more logs than it had. **The new predicate leaves 0 in that direction and 0 in the reverse direction.**
- **The three cases the brief names behave correctly.** A log ending `2026-09-13T11:00:00Z DONE r994 verdict CONFIRMED` beside a real report comes back byte-identical, and so does one ending `[11:00:00Z] DONE r998 verdict CONFIRMED`, which is the bracketed shape this round's own log uses. A `DONE` seventh from the end gets `FAILED` appended, and the hook reads that log as open too, so the two agree.
- **A lowercase `done` still gets `FAILED` written under a success.** Both readers miss it, so they agree and the log is corrupted anyway. This is r906's "further gap the two predicates share" and it did not reach the record.

**THE RESIDUAL: THE PATTERNS AGREE AND THE WINDOWS DO NOT.** [loop_stop.py:462](../.claude/hooks/loop_stop.py#L462) is `[l for l in lines[-6:] if l.strip()]`, the non-blank lines among the last six PHYSICAL lines. [salvage_reviewer.py:63](../scripts/lib/salvage_reviewer.py#L63) is `[l for l in ... if l.strip()][-6:]`, the last six NON-BLANK lines. The hook's window is therefore always a subset of the tool's, so the tool can read closed where the hook reads open and never the reverse.

- **Crafted and confirmed.** A log whose `DONE` is sixth from the end with a blank line beneath it is read closed by the tool, which leaves it alone, and open by the hook. **That is the direction that silences the loop rather than blocking it**, which is the one failure mode `_close_log` exists to prevent, so the residual sits on the expensive side.
- **No log on disk is currently in that split**, so this is latent rather than live today. It becomes live the moment an agent's last write ends in a blank line, which is a formatting accident rather than a protocol violation.
- **The docstring's claim is now true and the repair r906 asked for is still not made.** r906 wrote "the fix is one character class, shared between the two files rather than retyped", and the fold retyped it into a named constant. Two copies of one rule are what drifted, and there are still two.
